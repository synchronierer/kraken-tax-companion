# Contributing

Thank you for contributing to Kraken Tax Companion.

## Before You Start

Read [MASTERPLAN.md](MASTERPLAN.md), the architecture documentation, and all
relevant architectural decision records. Open an issue before starting a
change that alters architecture, public APIs, or data semantics.

## Development Workflow

1. Create a focused branch from the default branch.
2. Document intended behavior before implementation.
3. Add or update automated tests.
4. Run all quality checks locally.
5. Use a Conventional Commit message.
6. Open a pull request with motivation, design notes, and verification steps.

Every pull request requires review. Changes must be auditable, typed, tested,
documented, and limited to one coherent concern.

## Local Checks

```bash
make check
```

See [docs/contributing.md](docs/contributing.md) for the detailed workflow.
